## ⚽ Возможности

- **Мониторинг live‑матчей** в реальном времени (обновление каждые 60–120 секунд).
- **Гибкая фильтрация** по множеству параметров:
  - Время матча
  - Общая статистика (голы, угловые, удары, удары в створ, жёлтые карточки) – суммарно и для каждой команды
  - Разница статистики между хозяевами и гостями (home – away)
  - Коэффициенты (П1, П2, ничья, тотал 2.5) – с поддержкой live‑коэффициентов
  - Средние показатели в личных встречах (H2H) и в последних матчах команд
- **Чёрный список лиг** – исключение нежелательных турниров.
- **Уведомления в Telegram** (через прямого бота или BotGate).
- **Экспорт срабатываний** в Excel.
- **Веб-интерфейс** для управления фильтрами и просмотра истории сигналов.
- **Редактирование и удаление фильтров**, присвоение имён.
- **Мгновенное отключение/удаление фильтров** – без перезапуска планировщика.
- **История сигналов** с деталями матча и статусом фильтра, кнопка очистки истории.

## 🚀 Установка и запуск

1. **Клонировать репозиторий**
   ```bash
   git clone https://github.com/pippopil/Footbalmonitor.git
   cd Footbalmonitor
```

2. Создать виртуальное окружение (рекомендуется)
   ```bash
   python -m venv venv
   source venv/bin/activate      # Linux/Mac
   # или
   venv\Scripts\activate         # Windows
   ```
3. Установить зависимости
   ```bash
   pip install -r requirements.txt
   ```
   На Windows используйте py -m pip install -r requirements.txt.
4. Настроить app/config.py
   · Укажите токен Telegram-бота (TELEGRAM_BOT_TOKEN) – получите у @BotFather.
   · Укажите DEFAULT_CHAT_ID – свой chat_id (узнайте через @userinfobot).
   · При необходимости укажите API-ключ SStats (SSTATS_API_KEY). Без ключа лимит 30 запросов/мин на IP.
   · Интервал проверки CHECK_INTERVAL по умолчанию 120 секунд – можно изменить.
5. Создать папку data (если её нет)
   ```bash
   mkdir data
   ```
6. Запустить проект
   ```bash
   python -m app.main
   ```
   На Windows: py -m app.main
7. Открыть веб-интерфейс – http://localhost:8000

🧩 Основные компоненты

sstats_client.py

Клиент для SStats API. Реализует:

· get_live_matches() – получение матчей на сегодня.
· get_match_details(match_id) – детальная статистика (голы, угловые, удары, ЖК).
· get_match_odds(match_id, live=True) – коэффициенты (live или прематч).
· get_head_to_head(team1, team2, limit) – агрегация личных встреч (средние показатели).
· get_team_recent_matches(team_id, venue, limit) – средние показатели команды в последних N матчах.
· Ограничение частоты запросов (2 секунды между вызовами) для соблюдения лимитов.

filter_engine.py

Принимает матч, статистику, коэффициенты и список фильтров. Проверяет все условия (время, голы, угловые, удары, разницу, коэффициенты, H2H, последние матчи). Возвращает список фильтров, под которые подходит матч. Включено подробное DEBUG-логирование для отладки.

scheduler.py

· Запускается в фоновом потоке через APScheduler.
· Каждые CHECK_INTERVAL (по умолчанию 120 сек) опрашивает SStats на предмет live-матчей.
· Для каждого матча получает статистику и коэффициенты, проверяет активные фильтры.
· Ключевая особенность: фильтры перепроверяются на актуальность (активность и существование) перед каждым матчем, поэтому отключение/удаление применяется мгновенно, без перезапуска.
· При срабатывании фильтра:
  · Формирует сообщение и отправляет в Telegram.
  · Записывает сигнал в Excel.
  · Сохраняет сигнал в БД (таблица triggered_matches).

telegram_bot.py

· Реализует команду /start – регистрирует пользователя (создаёт запись в users).
· Использует python-telegram-bot с асинхронным polling.

database.py

· SQLite-обёртка с функциями CRUD для всех сущностей.
· Таблицы: users, filters, blacklisted_leagues, triggered_matches.
· Автоматические миграции: при добавлении новых полей (например, name, diff_*) они добавляются через ALTER TABLE.

web/routes.py

· FastAPI-маршруты: главная, создание/редактирование фильтра, список сигналов, управление чёрным списком.
· Использует собственный Jinja2 Environment с отключённым кэшем (для предотвращения ошибок unhashable type).
· Все шаблоны рендерятся вручную с возвратом HTMLResponse.

🔌 Интеграция с SStats API

Эндпоинт Метод в клиенте Назначение
GET /leagues get_leagues() Список всех лиг
GET /games/list?today=true get_live_matches() Live-матчи (сегодня)
GET /games/{id} get_match_details(id) Детальная статистика матча
GET /odds/live/{gameId} get_match_odds(id, live=True) Live-коэффициенты
GET /games/glicko/{id} get_glicko(id) Прогнозы Glicko 2 (задел на будущее)
GET /games/list?team1=X&team2=Y&ended=true get_head_to_head(team1, team2) Личные встречи (агрегированные средние)
GET /games/list?team=X&ended=true get_team_recent_matches(team, venue) Последние матчи команды (средние)

Лимиты: без ключа – 300 запросов/мин на всех пользователей или 30/мин на IP. Клиент автоматически выдерживает паузу 2 секунды между запросами.

🌐 Веб-интерфейс

Главная страница (/)

· Таблица всех фильтров с колонками: ID, название, время, голы, угловые, разница голов, коэффициенты, статус (активен/отключён).
· Кнопки действий: ✏️ редактировать, ⏸/▶ включить/выключить, 🗑 удалить.
· Кнопки перехода: «Создать новый фильтр», «Управление чёрным списком», «Сигналы».

Создание/редактирование фильтра (/filter/new, /filter/edit/{id})

· Поле «Название фильтра» (обязательное).
· Вкладки: «Общие», «Статистика», «Коэффициенты», «H2H / Анализ».
· Все параметры сгруппированы логически и имеют значения по умолчанию.
· При редактировании форма предзаполняется текущими данными.

Сигналы (/signals)

· Список всех сработавших сигналов с деталями матча (команды, счёт, время, статус матча).
· Отображается активность фильтра (🟢 активно / 🔴 отключено).
· Кнопка «Очистить все» – удаляет всю историю сигналов (с подтверждением).

Чёрный список лиг (/leagues)

· Список всех доступных лиг с возможностью добавить/удалить из чёрного списка.
· Исключённые лиги не участвуют в проверке фильтров.

⚠️ Известные проблемы и решения

Проблема Решение
Ошибка unhashable type: 'dict' при рендеринге шаблонов Используется ручной Jinja2 Environment с cache_size=0 и auto_reload=True.
Коэффициенты равны 0 Используйте live-коэффициенты (live=True в get_match_odds), либо установите диапазон 0–100 в фильтре.
Фильтр не срабатывает Включите DEBUG-логирование (в main.py поставьте level=logging.DEBUG), чтобы увидеть, какое условие не проходит.
После отключения фильтра сигналы всё равно идут В новой версии планировщик перепроверяет фильтры перед каждым матчем – проблема решена.
Слишком много запросов к API (предупреждение о превышении лимита) Увеличьте CHECK_INTERVAL в config.py (по умолчанию 120 секунд) или получите API-ключ SStats.
Бот не отвечает или не регистрирует пользователя Проверьте токен, убедитесь, что бот не запущен в другом месте, и что интернет-соединение стабильно.
Excel-файл не создаётся Убедитесь, что папка data существует и доступна для записи.
